# Git 自动保存

每次任务结束（一个回合的 `turn/end` 落盘之后），插件会检查当前会话的工作目录：有改动就 `git add -A .` 并提交一次，没有改动就什么也不做。每个任务因此都留下一个可回滚的本地检查点。

## 行为

- **只提交，不推送**（默认）。不联网、不访问远程，历史完全留在本机 `.git` 里。
  把 `push` 设为 `true` 后，每次提交完会顺手 `git push` 到 `origin` 的当前分支——
  **推送失败不会丢提交**：本地提交照常保留，只写一条警告日志。没有配置 remote 的仓库会静默跳过。
- **按目录隔离。** 提交只在会话的工作目录范围内进行：工作目录是仓库根目录时就是整仓；是子目录时只提交该子目录，仓库其他位置的暂存内容不受影响。
- **遵循 `.gitignore`。** `node_modules/`、虚拟环境等被忽略的路径不会被提交。
- **不在仓库里就跳过。** 工作目录不在任何 git 仓库内时，插件静默跳过（debug 日志），不会报错打扰。
- **子代理不单独提交。** 默认只为顶层会话记录检查点，子代理的回合不会单独产生提交。

## 提交信息

提交标题取自本次任务最后一条用户消息（截断到 60 字），正文记录时间、会话 id、回合号，以及 `--shortstat` 的文件统计：

```
dsh: 把周报脚本改成读取新表格

auto-saved at 2026-11-22T15:20:31.004Z
session 4f1c2a90 · turn 7
 2 files changed, 31 insertions(+), 4 deletions(-)
```

## 配置

在 **插件** 页面里修改该插件的配置，或直接改 profile 的 `cordis.patch.yml` 中 `git-autosave` 那一行：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 关掉后不注册任何监听，等于停用自动提交。 |
| `topLevelOnly` | `true` | 只处理顶层会话；设为 `false` 后子代理回合也会提交。 |
| `messagePrefix` | `dsh` | commit 标题前缀，最终形如 `dsh: <任务摘要>`。 |
| `includeStat` | `true` | 是否在提交正文里附加 `--shortstat` 统计。 |
| `timeoutMs` | `30000` | 单条 git 命令的超时；超时即放弃本次检查点，下个任务重新尝试。 |
| `push` | `false` | 提交后是否 `git push` 到 `origin` 的当前分支。开启后需主机已配置凭据（推荐 Git Credential Manager）。 |

## 使用前提

- 主机上有 git 可执行文件（本机为 2.13 以上），并且仓库已配置 `user.name` / `user.email`；缺失时 `git commit` 会失败并在日志里留下警告。
- 工作目录本身是一个 git 仓库。工作区第一次使用时已经 `git init`，此后每个任务结束都会自动产生提交。

## 自检

包内自带一份端到端测试，用真实的 git 仓库跑 `apply()` + `turn/end` 通知，覆盖正常提交、无改动、非仓库目录、子目录范围、子代理、停用、自定义前缀和连续两回合：

```
node plugins/git-autosave/test/e2e.mjs
```

## 已知限制

- 只记录文件系统层面的改动。被 `.gitignore` 排除的产物、以及只存在于内存里的状态不会被保存。
- 一次提交覆盖整个任务（一个回合）的净改动，而不是每次工具调用一提交；任务中途的执行细节需要看会话日志，而不是 git 历史。
- 命令在后台运行，不阻塞会话结束；提交失败只写日志，不会打断任务。
- 与 Harness 自带的"本次改动"卡片各自独立工作：该卡片比较工作树快照，与提交互不影响。
